The pipeline

Nine gates, in order.

Each stage creates evidence the next stage can trust. Skipping ahead makes later consistency work much harder.

  1. 01
    Scope

    Define content, platform, permissions, patch format, and review ownership.

  2. 02
    Canonical source

    Prove which script and auxiliary tables the shipped runtime actually uses.

  3. 03
    Lossless table

    Preserve every engine row and assign immutable translation keys.

  4. 04
    Terminology

    Lock names, aliases, items, ranks, organizations, and typography.

  5. 05
    Grammar

    Document the title's recurring structural traps with concrete examples.

  6. 06
    Style & batches

    Define voice and presentation rules, then split by scene with context.

  7. 07
    Translation loop

    Generate bounded drafts, validate them, and merge by stable ID only.

  8. 08
    Three-pass QA

    Run structural, linguistic, and in-engine review as separate gates.

  9. 09
    Release

    Resolve review items, rebuild reproducibly, and distribute only patch data.

Guardrails

What the model is never trusted to protect alone.

◆

Source integrity

Source text, commands, IDs, and control fields remain immutable.

◆

Terminology

Approved forms and context rules live outside individual prompts.

◆

Uncertainty

Inference, rumor, conditionals, and reveal timing remain intact.

◆

Markup

Tags and variables are protected, restored, and compared mechanically.

◆

Merge safety

Outputs merge by stable ID and never silently replace prior work.

◆

Release quality

Passing a validator is necessary, but never substitutes for editorial QA.
