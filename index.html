The short version

  1. Verify the runtime source. A shipped game may contain obsolete or duplicate scripts.
  2. Export losslessly. Preserve every row and control field; give each translatable row a stable ID.
  3. Write the authorities first. Lock terminology and document recurring grammar traps with real examples.
  4. Batch by context. Translate scenes, not arbitrary character counts, with neighboring rows available.
  5. Protect structure mechanically. Tags, variables, commands, IDs, and source text are not entrusted to prompts.
  6. Merge by stable ID. Never overwrite existing work silently; record prompt, model, status, and notes.
  7. Review three times. Structural checks, bilingual editing, then in-engine testing.
  8. Release a patch, not source data. Keep originals private and make the build reproducible.

Core rules

  • The canonical source and control columns stay immutable.
  • Names, aliases, ranks, and recurring items use an approved authority.
  • Rumor, inference, conditionals, vague referents, and reveal timing remain intact.
  • Production-only sprite labels never leak into displayed names.
  • MT output is a draft until reviewed.

QA passes

Structural
IDs, rows, tags, placeholders, variables, and missing text.
Linguistic
Meaning, agency, negation, certainty, terminology, voice, and fluency.
In-engine
Layout, choices, timing, formatting, saves, menus, and patch behavior.
